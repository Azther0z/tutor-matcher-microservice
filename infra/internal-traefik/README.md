# Internal Traefik

The internal Traefik instance provides private owner-specific REST names (`auth.internal`, `booking.internal`, `tutor.internal`, `wallet.internal`, `review.internal`, `messaging.internal`, and `notification.internal`) and gRPC names for Auth, Booking, Tutor, Wallet, and Review on the backend network. It is separate from the public gateway and has no published ports. The public gateway continues to discover owner tasks and routes its contracted public API directly to those tasks. Auth operation and admission paths remain on the direct public-gateway-to-owner route.

All seven owners advertise HTTP services, and the five gRPC owners advertise separate gRPC services to the internal instance. Docker Compose uses the Docker provider; hosted Swarm uses the Swarm provider with load balancing through individual task addresses. Both gRPC hops use h2c and standard gRPC Health checks. No proxy retry is configured. During Docker API discovery loss, Traefik retains its last dynamic configuration and continues active health checks; calls fail if all cached endpoints are unhealthy. Route files are generated separately for the Docker and Swarm providers from `contracts/operation-map.json`.

`npm run routes:internal:check` verifies generated owner routes. `npm run test:internal-traefik` runs manifest checks, a real Compose fixture, and a rendered Swarm manifest parse. The Compose qualification covers persistent HTTP and gRPC distribution, authentication, task scaling, unhealthy endpoints, discovery API outage with task replacement, zero backends, and recovery; its isolated stack is removed at exit.

`npm run qualify:internal-traefik:swarm` is a separate real-Swarm qualification. It requires an already active local manager and `INTERNAL_TRAEFIK_SWARM_QUALIFY=1`. It creates a uniquely named stack, exercises Swarm task discovery, two-proxy failure recovery, task scaling, cached endpoints during Docker API outage, authentication and health behavior, then removes only that stack. The synthetic single-node Swarm qualification passed all five checkpoint groups, and its stack, services, and networks were removed. The fixture does not qualify the full application, a hosted deployment, or a multi-node Swarm. See [qualification evidence](../../docs/evidence/internal-traefik.md).
